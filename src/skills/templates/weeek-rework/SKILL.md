Задача: возьми следующую задачу из колонки **«Доработать ИИ»** (role `AI_REWORK`) — это работа, которую ИИ уже сдавал, а человек проверил и вернул с замечаниями — исправь её и верни на проверку. Доска задаётся проектным `.weeek-mcp.json` (`boardUrl`), номера колонок не хардкодятся — переходы делаются по ролям.

Две очереди НЕ смешиваются: новые задачи («Ошибки»/«Доработки») берут `/weeek-errors`, `/weeek-tasks`, `/weeek-any`. Этот скилл работает ТОЛЬКО с возвратами.

## Правило №0: КАК вызывать weeek-инструменты (важно в этом харнессе)

`weeek_*` — это **MCP-инструменты** (полные имена `mcp__weeek__weeek_*`). Вызывай их как **нативный tool-call**, точно как Read / Write / Edit. НЕ иначе:

- ❌ НЕ запускай `weeek_list_rework_tasks` как **Bash-команду** — это не shell-команда, получишь `command not found` (exit 127).
- ❌ НЕ делегируй вызов **субагенту** (Agent/Task) — вызывай сам.
- ❌ НЕ пиши скрипты-обёртки и НЕ ходи в API через curl/fetch.

Если нужного `weeek_*` нет в твоём немедленном списке функций — он **отложенный (deferred)**. Тогда СНАЧАЛА одним вызовом `ToolSearch` подгрузи схемы (перечисли через запятую полные имена, что нужны скиллу):

`select:mcp__weeek__weeek_list_rework_tasks,mcp__weeek__weeek_get_task,mcp__weeek__weeek_move_task,mcp__weeek__weeek_finish_task,mcp__weeek__weeek_ask_question`

После ответа `ToolSearch` их схемы появятся в блоке `<functions>` — и они **сразу становятся callable**. Никакой отдельной «активации» нет: увидел схему → вызывай инструмент напрямую.

## Правило №1: только MCP `weeek_*` tools

Любой `curl` / `fetch` / Bash-запрос к `api.weeek.net` **ЗАПРЕЩЁН**. Это дырявит permissions и обходит безопасный интерфейс MCP. Если нужной операции нет в MCP — остановись и сообщи пользователю, чтобы он добавил её в сервер `mcp-weeek`. Не обходи через raw HTTP.

## Шаги

1. **`weeek_list_rework_tasks`** — читает ТОЛЬКО колонку «Доработать ИИ». Возьми первую задачу: `priority` DESC (3=high), тай-брейк `id` ASC. Если пусто — сообщи «В колонке 'Доработать ИИ' нет задач» и закончи сессию (не бери задачи из других колонок без разрешения).

2. **`weeek_get_task({ taskId })`** — прочитай задачу целиком. Ключевое здесь:
   - **замечание человека** — что именно не устроило в прошлой сдаче;
   - поле **«ИИ-диалог»** — история вопросов ИИ и ответов человека, читай её ПОЛНОСТЬЮ: ответ на твой прошлый вопрос лежит именно там;
   - поле **«ИИ-отчёт»** — что было сделано в прошлый раз (отправная точка, а не готовая правда);
   - execution rules во втором content-блоке ответа — следуй им СТРОГО.

3. **`weeek_move_task({ taskId, role: "AI_IN_PROGRESS" })`** — клейм в «ИИ в работе». Сразу после чтения, до правок: снимает задачу с очереди возвратов, чтобы её не подхватил параллельный агент.

4. **Исправь по замечанию**:
   - сначала пойми, что реально сломано/недоделано — прошлый отчёт мог быть неточным, проверяй по коду (Read, Grep, трассировка);
   - правь по существу замечания, не переписывай смежное «заодно»;
   - для любой библиотеки из стека — `mcp__context7__resolve-library-id` → `mcp__context7__query-docs` (актуальная дока);
   - следуй правилам проекта: корневой [{{AGENT_DOC}}]({{AGENT_DOC}}) и [{{RULES_DIR}}]({{RULES_DIR}}), если они есть в репозитории;
   - перед отчётом прогони проверки этого репозитория (type-check / lint / тесты — те, что приняты в проекте).

5. **`weeek_finish_task({ taskId, report: "<текст>" })`** — одним апдейтом пишет «ИИ-отчёт» и возвращает задачу в «Ожидает релиза» (role `AWAITING_RELEASE`). В report по возврату укажи явно: **что было замечание → что изменено → чем проверено**, какие файлы тронуты (плейн-текст, без HTML). Прошлый отчёт перезаписывается — не ссылайся на него как на «см. выше», пиши самодостаточно.

   В «ВЫПОЛНЕНО ИИ» (role `AI_DONE`) задачу **не** перемещай — это делает `/weeek-release` после деплоя.

## Если замечание непонятно

**`weeek_ask_question({ taskId, question: "<конкретный вопрос>" })`** — допишет вопрос с меткой времени в «ИИ-диалог» (историю не затирает) и перенесёт задачу в «Обсудить» (role `DISCUSS`). После этого **остановись** и скажи пользователю, что ждём ответа: человек ответит в «ИИ-диалоге» и вернёт задачу в «Доработать ИИ» — тогда её снова возьмёт этот скилл.

Вопрос должен быть конкретным и с вариантами («ждём A или B?»), а не «уточните, пожалуйста». Не угадывай молча и не сдавай наугад вторую итерацию.

## Безопасность

- Скилл работает только с колонкой «Доработать ИИ» → «ИИ в работе» → «Ожидает релиза» (или → «Обсудить» при вопросе). Другие колонки не трогает.
- `weeek_reject_task` в этой линии по умолчанию НЕ применяется: задачу уже проверял человек. Если после разбора видно, что замечание основано на недоразумении — задай вопрос через `weeek_ask_question`, а не отклоняй.
- Если `weeek_finish_task` вернул ошибку — остановись и покажи ответ пользователю, не пытайся обойти через `weeek_complete_task` или сырой HTTP.
