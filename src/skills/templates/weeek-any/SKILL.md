name: weeek-any
description: Take the next pending task from the Weeek feedback board (either source column «Ошибки» or «Доработки») and run it end-to-end via MCP weeek_* tools only.
---

Задача: возьми следующую задачу с Weeek-доски из колонок-источников **«Ошибки»** или **«Доработки»** и выполни её end-to-end. Доска задаётся проектным `.weeek-mcp.json` (`boardUrl`), номера колонок не хардкодятся — движения делаются по ролям.

Очередь возвратов после проверки человеком — **«Доработать ИИ»** (role `AI_REWORK`) — этим скиллом НЕ берётся, для неё есть `/weeek-rework`.

## Правило №0: КАК вызывать weeek-инструменты (важно в этом харнессе)

`weeek_*` — это **MCP-инструменты** (полные имена `mcp__weeek__weeek_*`). Вызывай их как **нативный tool-call**, точно как Read / Write / Edit. НЕ иначе:

- ❌ НЕ запускай `weeek_list_pending_tasks` как **Bash-команду** — это не shell-команда, получишь `command not found` (exit 127).
- ❌ НЕ делегируй вызов **субагенту** (Agent/Task) — вызывай сам.
- ❌ НЕ пиши скрипты-обёртки и НЕ ходи в API через curl/fetch.

Если нужного `weeek_*` нет в твоём немедленном списке функций — он **отложенный (deferred)**. Тогда СНАЧАЛА одним вызовом `ToolSearch` подгрузи схемы (перечисли через запятую полные имена, что нужны скиллу), например:

`select:mcp__weeek__weeek_list_pending_tasks,mcp__weeek__weeek_get_task,mcp__weeek__weeek_move_task,mcp__weeek__weeek_finish_task,mcp__weeek__weeek_ask_question,mcp__weeek__weeek_reject_task`

После ответа `ToolSearch` их схемы появятся в блоке `<functions>` — и они **сразу становятся callable**. Никакой отдельной «активации» нет: увидел схему → вызывай инструмент напрямую.

## Правило №1: только MCP `weeek_*` tools

Любой `curl` / `fetch` / Bash-запрос к `api.weeek.net` **ЗАПРЕЩЁН**. Это дырявит permissions и обходит безопасный интерфейс MCP. Если нужной операции нет в MCP — остановись и сообщи пользователю, чтобы он добавил её в сервер `mcp-weeek`. Не обходи через raw HTTP.

## Шаги

1. **`weeek_list_pending_tasks`** — получи pending-задачи. Выбор задачи:
   - Сначала по `priority` DESC (3=high, 2=medium, 1=low, 0/null=none)
   - Тай-брейк: по `id` ASC (старые первые)
   - Из какой колонки-источника («Ошибки» или «Доработки») — для выбора НЕ важно
   - Если обе колонки пусты — сообщи «Pending задач нет» и закончи

2. **`weeek_get_task({ taskId })`** — прочитай полные детали. Во втором content-блоке ответа — execution rules. Следуй им СТРОГО.

3. **`weeek_move_task({ taskId, role: "AI_IN_PROGRESS" })`** — клейм в «ИИ в работе». Делай это СРАЗУ после чтения, до начала кода: снимает задачу с колонки-источника, чтобы параллельные агенты её не подхватили.

4. **Выполни работу** по execution rules:
   - Разбери проблему/задачу детально (Read, Grep, трассировка), пойми существующие паттерны в коде
   - Для любой библиотеки из стека — `mcp__context7__resolve-library-id` → `mcp__context7__query-docs` (актуальная дока)
   - Следуй правилам проекта: корневой [{{AGENT_DOC}}]({{AGENT_DOC}}) и [{{RULES_DIR}}]({{RULES_DIR}}), если они есть в репозитории
   - Только 100% рабочее решение (никаких «должно сработать» / «попробуйте»)
   - Перед отчётом прогони проверки этого репозитория (type-check / lint / тесты — те, что приняты в проекте: смотри `package.json` scripts, Makefile или CI-конфиг)

5. **`weeek_finish_task({ taskId, report: "<текст>" })`** — обязательный финальный шаг: одним апдейтом пишет отчёт в custom field «ИИ-отчёт» (UUID резолвится по имени, передавать не нужно) и переносит задачу в «Ожидает релиза» (role `AWAITING_RELEASE`). Формат report: коротко что изменил/добавил, какие файлы тронуты, вердикт (плейн-текст, без HTML). Отдельные `weeek_set_ai_report` + `weeek_move_task` больше не нужны — так отчёт и переход никогда не расходятся.

   Задача готова, но ещё не выкачена на dev/prod. После `git push` + деплоя пользователь сам вызовет `/weeek-release`, который перенесёт задачу в «ВЫПОЛНЕНО ИИ» (role `AI_DONE`). **НЕ перемещай в `AI_DONE` руками.**

## Если задача неоднозначна

- **До клейма** (шаг 3) — уточняй у пользователя через AskUserQuestion, задача остаётся в исходной колонке.
- **После клейма**, если пользователя рядом нет или вопрос требует его решения — **`weeek_ask_question({ taskId, question: "<вопрос>" })`**: допишет вопрос с меткой времени в поле «ИИ-диалог» (историю не затирает) и перенесёт задачу в «Обсудить» (role `DISCUSS`). На этом останавливайся: человек ответит в «ИИ-диалоге» и вернёт задачу в «Доработать ИИ» — оттуда её подхватит `/weeek-rework`.
- Возврат в исходную колонку через `weeek_move_task` (`role: "SOURCE_ERRORS"` или `"SOURCE_IMPROVEMENTS"`) — только если задача взята ошибочно и вопроса к человеку нет.
- Если разбор показал, что правка не нужна (устарело, уже починено, дубль, неверно понято) — **`weeek_reject_task`** с конкретным отчётом проверки, а не косметический диф.
