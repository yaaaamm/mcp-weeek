Задача: вызывается пользователем ВРУЧНУЮ после `git push` + деплоя на dev/prod.
Перенести ВСЕ задачи из колонки **«Ожидает релиза»** (role `AWAITING_RELEASE`) в колонку **«ВЫПОЛНЕНО ИИ»** (role `AI_DONE`). Доска задаётся проектным `.weeek-mcp.json` (`boardUrl`), номера колонок не хардкодятся.

## Правило №0: КАК вызывать weeek-инструменты (важно в этом харнессе)

`weeek_*` — это **MCP-инструменты** (полные имена `mcp__weeek__weeek_*`). Вызывай их как **нативный tool-call**, точно как Read / Write / Edit. НЕ иначе:

- ❌ НЕ запускай `weeek_list_pending_tasks` как **Bash-команду** — это не shell-команда, получишь `command not found` (exit 127).
- ❌ НЕ делегируй вызов **субагенту** (Agent/Task) — вызывай сам.
- ❌ НЕ пиши скрипты-обёртки и НЕ ходи в API через curl/fetch.

Если нужного `weeek_*` нет в твоём немедленном списке функций — он **отложенный (deferred)**. Тогда СНАЧАЛА одним вызовом `ToolSearch` подгрузи схемы (перечисли через запятую полные имена, что нужны скиллу), например:

`select:mcp__weeek__weeek_list_columns,mcp__weeek__weeek_list_tasks,mcp__weeek__weeek_move_task`

После ответа `ToolSearch` их схемы появятся в блоке `<functions>` — и они **сразу становятся callable**. Никакой отдельной «активации» нет: увидел схему → вызывай инструмент напрямую.

## Правило №1: только MCP `weeek_*` tools

Любой `curl` / `fetch` / Bash-запрос к `api.weeek.net` **ЗАПРЕЩЁН**. Если нужной операции нет в MCP — остановись и сообщи пользователю, чтобы он расширил `mcp-weeek`. Не обходи через raw HTTP.

## Шаги

1. **`weeek_list_columns()`** — получить колонки доски. Найди id колонки «Ожидает релиза» по имени (регистр не важен).

2. **`weeek_list_tasks({ boardColumnId: <id из шага 1> })`** — получить задачи в этой колонке.

   Начиная с mcp-weeek 1.8.0 инструмент **сам проходит все страницы** `/tm/tasks` и отдаёт колонку целиком: `totalCount` + компактный `tasks[]`. Крутить пагинацию руками не надо.

   ⚠️ Две проверки ответа перед работой:
   - **`truncated: true`** — упёрлись в предохранитель, список НЕполный. Останови работу и скажи пользователю.
   - **В ответе есть `hasMore` и нет `totalCount`** — загружен СТАРЫЙ сервер (до 1.8.0), он отдаёт только ~20 задач за вызов. Скажи пользователю обновить `mcp-weeek` до 1.8.0+ (пересобрать/переустановить) и перезапустить клиента. До этого проходи колонку повторными циклами «list → move»: перенесённые уходят из колонки, и следующий `weeek_list_tasks` отдаёт следующую порцию — пока `hasMore` не станет `false`.

3. Из ответа взять задачи, которые реально лежат в целевой колонке и не завершены:

   ```
   isCompleted === false
   И (boardColumnId === <id> ИЛИ любой элемент locations[] имеет boardId === <доска> и boardColumnId === <id>)
   ```

   ⚠️ **Фильтровать ТОЛЬКО по верхнеуровневому `boardColumnId` НЕЛЬЗЯ.** Задача может лежать сразу на нескольких досках; верхний `boardColumnId` показывает колонку ДРУГОЙ доски, а членство в нашей живёт в массиве **`locations[]`** (сервер отдаёт его именно у таких задач). Реальный инцидент 19.08.2026: задачи #3210 и #3208 (`boardColumnId: 624`, доска 175 «Спринты») висели в «Ожидает Релиза» доски 133 через `locations` — и были молча пропущены.

   Если список пуст — сообщи «В колонке 'Ожидает релиза' нет задач» и закончи. Не трогай другие колонки.

4. Для КАЖДОЙ задачи вызови **`weeek_move_task({ taskId, role: "AI_DONE" })`**. Все вызовы независимы — отправь их параллельно несколькими tool-calls в одном сообщении.

5. **Контрольный `weeek_list_tasks` по той же колонке** — обязателен перед сводкой. Ожидаемый результат: пустой `tasks[]` при `truncated: false`. Что-то осталось — колонка не разобрана, вернись к шагу 3 и добери остаток.

   ⚠️ НЕ рапортуй об итогах, не увидев пустую колонку своими глазами. Число перенесённых в сводке — фактическое, а не «сколько было в первом ответе».

6. По итогу выведи краткую сводку:
   ```
   Перенесено N задач из «Ожидает релиза» → «ВЫПОЛНЕНО ИИ»:
     #<id1> «<title1>»
     #<id2> «<title2>»
     ...
   ```
   Без отчётов в `ИИ-отчёт`, без правок кода, без git-операций.

## Безопасность

- Скилл НЕ редактирует код, НЕ делает git-операции, НЕ пишет в `ИИ-отчёт` — только `weeek_move_task` «Ожидает релиза» → «ВЫПОЛНЕНО ИИ» (role `AI_DONE`).
- НЕ трогать другие колонки — только «Ожидает релиза» → «ВЫПОЛНЕНО ИИ».
- Если `weeek_move_task` вернул `success: false` — остановись и покажи пользователю ответ (не пытайся обходить через `weeek_complete_task` или сырой HTTP).
- Если в «Ожидает релиза» ноль задач — это НЕ ошибка, просто сообщи и заверши.
- **Финальная проверка перед сводкой:** последний `weeek_list_tasks` по колонке обязан вернуть пустой `tasks[]` при `truncated: false`. Не увидел этого — колонка не разобрана, работа не закончена.
