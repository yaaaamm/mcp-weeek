Задача: подготовить Weeek-доску этого проекта к AI-воркфлоу — досоздать недостающие колонки и текстовые поля «ИИ-отчёт»/«ИИ-диалог». Доска берётся из проектного `.weeek-mcp.json` (`boardUrl`).

## Два пути: CLI и MCP

- **CLI (основной, если есть терминал):** `mcp-weeek init-board` — предпросмотр, `mcp-weeek init-board --yes` — применить, `mcp-weeek doctor` — полная диагностика (конфиг, токен, доступ к доске, колонки/поля, клиентские конфиги, скиллы, MCP-handshake). Требует `.weeek-mcp.json` в корне проекта; если его нет — сначала `mcp-weeek setup`.
- **MCP (из чата):** `weeek_init_board` — то же самое инструментом, шаги ниже.

## Правило №0: КАК вызывать weeek-инструменты (важно в этом харнессе)

`weeek_*` — это **MCP-инструменты** (полные имена `mcp__weeek__weeek_*`). Вызывай их как **нативный tool-call**, точно как Read / Write / Edit. НЕ иначе:

- ❌ НЕ запускай `weeek_init_board` как **Bash-команду** — это не shell-команда, получишь `command not found` (exit 127).
- ❌ НЕ делегируй вызов **субагенту** (Agent/Task) — вызывай сам.
- ❌ НЕ пиши скрипты-обёртки и НЕ ходи в API через curl/fetch.

Если нужного `weeek_*` нет в твоём немедленном списке функций — он **отложенный (deferred)**. Тогда СНАЧАЛА одним вызовом `ToolSearch` подгрузи схемы:

`select:mcp__weeek__weeek_init_board,mcp__weeek__weeek_list_columns`

После ответа `ToolSearch` их схемы появятся в блоке `<functions>` — и они **сразу становятся callable**. Никакой отдельной «активации» нет: увидел схему → вызывай инструмент напрямую.

## Правило №1: только MCP `weeek_*` tools

Любой `curl` / `fetch` / Bash-запрос к `api.weeek.net` **ЗАПРЕЩЁН**. Всё через MCP `mcp-weeek` или его CLI.

## Шаги

0. **Проверка конфигурации проекта.** Токена в клиентских конфигах нет: `.weeek-mcp.json` хранит только `boardUrl` + ссылку на переменную, а сам `WEEEK_API_TOKEN` лежит в gitignored env-файле.
   - `.weeek-mcp.json` есть в корне? Если нет — скажи пользователю запустить `mcp-weeek setup` (спросит URL доски и путь к env-файлу) и остановись.
   - `git check-ignore <env-файл>` — файл с токеном обязан игнорироваться. Если нет — допиши его в `.gitignore`.
   - Клиентские конфиги (`.mcp.json`, `.codex/config.toml`, `.agents/mcp_config.json`) содержат машинно-локальные абсолютные пути — они тоже должны быть в `.gitignore`. `.weeek-mcp.json` наоборот коммитится.
   - Если какой-то из этих файлов уже отслеживается git'ом (`git ls-files --error-unmatch <файл>` успешно) — предупреди пользователя и предложи `git rm --cached <файл>`.

1. **`weeek_init_board({ dryRun: true })`** — сухой прогон. Покажи пользователю план: какие колонки/поля будут созданы (`status: "created"`), какие уже есть (`status: "existing"`). Ничего не пишется.

2. Покажи план и спроси подтверждение через **AskUserQuestion** («Создать перечисленное на доске?»). Если пользователь не подтвердил — остановись.

3. После «ок» — **`weeek_init_board({})`** (реальный прогон, `dryRun: false` по умолчанию). Выведи итог: сколько создано, id новых колонок, статус полей «ИИ-отчёт» и «ИИ-диалог».

4. (Опционально) если пользователь просит завести и ручные колонки человеческого воркфлоу («Ручная доработка», «Готово», «Принято Manual») — передай `includeOptional: true`.

## Заметки

- Инструмент идемпотентен: повторный запуск ничего не ломает, только досоздаёт отсутствующее.
- Поля создаются только на доске, где есть хотя бы одна задача. API Weeek показывает поля доски лишь через её задачи, и на пустой доске нельзя узнать, какие поля уже есть, — создание могло бы их задублировать. Тогда колонки создаются, поля получают статус `skipped`, а в отчёте `fieldsVisible: false`: попроси пользователя завести на доске любую задачу и повтори `weeek_init_board`.
- Колонки и поля матчатся ПО ИМЕНИ (регистр и лишние пробелы не важны) — существующие переиспользуются, дубли не создаются.
- Обязательный набор колонок — все, куда какой-либо `weeek_*` инструмент переносит задачу: «Ошибки», «Доработки», «Обсудить», «ИИ в работе», «Доработать ИИ», «Ожидает релиза», «ВЫПОЛНЕНО ИИ», «Подтвердить (у меня нет такой ошибки)» (цель `weeek_reject_task`).
- Обязательные текстовые поля: «ИИ-отчёт» (отчёт о выполнении, пишет `weeek_finish_task`) и «ИИ-диалог» (история вопросов/ответов, пишет `weeek_ask_question`). Без «ИИ-диалога» вопросы человеку падают с `BOARD_SCHEMA_INCOMPLETE`.
- Роли колонок: «Доработать ИИ» = `AI_REWORK` (возвраты после проверки человеком, скилл `/weeek-rework`), «Обсудить» = `DISCUSS` (задача ждёт ответа человека).
